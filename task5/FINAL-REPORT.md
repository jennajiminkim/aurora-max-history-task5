## 2. 개선 목표 및 작업 범위

기존 실측 NOAA 오로라 정보판의 `DAILY RECORDS` 영역에 `VIEW HISTORY` 버튼을 추가하고, 새 브라우저 탭이 아니라 **사이트 내부 폴더형 모달**에서 날짜별 MAX(OBSERVED) 기록을 보여준다. 막대그래프, 선택 날짜의 MAX/LATEST/MAX TIME(NOAA UTC), 전체 최고값/날짜를 표시하며 `×` 및 `Esc` 닫기와 키보드 선택을 지원한다.

- **MAX의 의미:** 하루 중 이 브라우저가 실제로 성공적으로 수신해 보관한 값 중 최고치다. NOAA의 전체 24시간 완전 관측 최고치를 의미하지 않는다.
- 브라우저별 `localStorage`에 저장하므로 다른 도메인, 다른 브라우저, 시크릿 창에는 과거 기록이 없을 수 있다. 기록이 없어도 모달은 열리고 빈 상태를 안내해야 한다.
- NOAA 조회, ASCII 애니메이션, 하루 1개 KST 레코드, 이벤트 아카이브, PREVIEW, 기존 VERIFICATION을 보존하고 합성 테스트 데이터를 실제 기록에 혼합하지 않는다.

## 3. 사전에 확정한 동일 조건

- **검사:** `T05-H01` ~ `T05-H10`, 정확히 10개. ID·입력·기대 출력 삭제, 완화, 변경하지 않음.
- **계약 파일 SHA-256:** `c03036a50a31473fcb6bce74226b6bda8d0ad8a0e770ed464cfed7ba455b2d23`.
- **공통 상한:** 최초 작업 요청부터 각 AI 최대 **45분**, 사용자 메시지 최대 **8회**. 도구/API 호출은 별도 실측 보고.
- **진행 순서:** A 시작 → A 중단·인계 → 별도 서비스의 B 대화 시작 → B 기능 마무리 → 코드 통합·재검사. A의 전체 채팅 대화를 B에 복사하지 않음.
- **첫 요청:** `COMMON-FIRST-REQUEST.md`를 동일 시작 지침으로 정했다. **B에게 동일한 문장을 실제로 전부 전달했는지에 대한 대화 원본 증거는 확인되지 않았다.**

## 4. 익명 A/B 결과 비교표

| 비교 항목 | AI A | AI B |
|---|---|---|
| 역할 | MAX 모델·날짜 정렬·막대/폴더형 기본 화면, 인계 | 닫기 및 날짜 선택 상세정보, 키보드 상호작용 보완 |

**비교의 해석:** A와 B가 같은 프로젝트를 각각 처음부터 완성한 독립 속도경쟁이 아니다. **A가 일부 기능을 남기고 중단한 후 B가 그 작업을 이어받는 연속 작업**이므로, B의 10/10 결과는 인수인계 후 결함 수정의 성공을 뜻한다. B가 2분 만에 전체 과제를 완성했다는 의미가 아니다. 45분 제한은 집중 구현시간이 아닌 전체 경과시간 23분으로 판정했다.

## 7. 결과 선택 기준 — 한 줄

**선택 기준 제안:** “인수인계 후 기능 완성도는 B가 더 좋았지만, 저장소 접근과 증거 기록까지 포함한 실무 흐름에서는 A가 수월했다. 따라서 단순 수정·검사에는 B, GitHub 연계·기록 관리에는 A를 선택하겠다.”  
※ 이는 결과 기반 **학생 판단용 초안**이며, 최종 선호는 작성자가 직접 확인한다.

## 8. 짧은 확인 방법 — 4줄

1. **위치:** https://aurora-max-history-task5.vercel.app/ → `DAILY RECORDS`.
2. **행동(최대 3단계):** `VIEW HISTORY` 클릭 → 저장된 날짜가 있으면 선택 → `×` 또는 `Esc`로 닫기.
3. **통과 모습:** 내부 폴더형 모달이 열리고 날짜별 MAX 막대 및 선택 날짜의 MAX/LATEST/NOAA UTC가 올바르다. 빈 기록은 `No records yet`으로 표시된다.
4. **안 될 때:** 창이 열리지 않음, 누락된 스크립트 404, 잘못된 MAX/시간, 닫기 오류 또는 화면 잘림. 새 브라우저의 기록 0건 자체는 오류가 아니다.

## 9. AI와 나의 판단 — 3줄

1. **AI에게 맡긴 일:** MAX 데이터 모델과 기록 화면 설계·구현, 모달/선택 상세 수정, 고정 10검사와 오류 분석.
2. **내가 직접 판단한 일:** 주제·화면 형태·고정 검사 10개·공통 45분/8회 상한 확정, 단계별 인계와 공개 사이트 배포 여부 결정.
3. **AI의 제안을 따르지 않은 일:** 별도 유료 개발 도구 사용을 대신해 일반 AI 채팅에서 작업하고, 필요한 파일을 GitHub 웹으로 업로드했다.

## 10. 제출 전 남은 확인

- **무로그인:** 시크릿 창에서 배포 URL이 열리는지 별도 확인. 일반 Chrome 실제 화면 작동은 2026-10-11 사진으로 확인함.
- **B의 도구 호출 근거:** 파일 업로드 이후 \`bash_tool\` 10회 + \`present_files\` 1회 = **11회**. 이는 **AI B가 자신의 실행 로그를 직접 세어 사용자에게 전달한 값**이며, 시스템 자동 집계값이나 세션 전체 총호출 수 확인값이 아니다. 11회 중 **1회는 셸 brace 확장 오류로 실패해 재시도**했으며, 이 오류를 고정 10검사의 실패 회차로 계산하지 않는다.
- **B 세션에서 여전히 미확인:** 시작 소스 SHA, \`HANDOFF.md\` 원문 SHA-256 동일성, B 내부 고정 10검사 오류 회차, 파일 업로드 이전의 도구 호출 수. 없는 수치를 0 또는 추정 수치로 기재하지 않음.
- A 도구 호출 수도 자동 집계되지 않아 **미확인**.
- 검증에 사용한 Playwright 실행 환경은 실제 서비스 데이터를 건드리지 않음.
- **재작업량 수치**는 제출 후 평가기가 소스 SHA 쌍으로 계산하는 항목이므로 임의로 기입하지 않음.
- 개인정보·인증 토큰·비밀키·AI 대화 전문을 공개하지 않음.
